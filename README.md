# Пульс города

«Пульс города» — работающий MVP платформы совместного контроля городской среды. Житель фиксирует проблему, другие жители независимо подтверждают её, городской оператор назначает службу, исполнитель публикует отчёт, а финальный результат проверяют оператор и жители. Исполнитель не может закрыть обращение самостоятельно.

## Что реализовано

- четыре серверные роли: житель, городской оператор, исполнитель и администратор;
- строгая машина из 16 статусов с историей и аудитом;
- интерактивная карта на 2ГИС MapGL JS API, кластеризация, фильтры и синхронизация карты с реестром;
- мобильный мастер создания обращения: геопозиция, точка, категория, фото, описание, поиск похожих проблем, автосохранение черновика и предпросмотр;
- безопасная загрузка JPEG/PNG/WebP до 8 МБ, удаление EXIF через повторное кодирование Sharp;
- независимые подтверждения и общественное голосование без повторного голоса;
- кабинеты оператора, исполнителя и администратора;
- обсуждения конкретного обращения, официальные ответы, ответы на сообщения и Socket.IO-обновления;
- миссии, репутация, достижения, серии полезных дней и «Здоровье района»;
- каталог из 14 достижений с полученными и ещё не полученными наградами, условиями и прогрессом по действиям аккаунта; при открытии профиля сервер сохраняет новые выполненные достижения, ранее полученные награды остаются;
- внутренние уведомления и готовый транспортный интерфейс для Telegram-бота;
- браузерный, Telegram и будущий MAX платформенные адаптеры;
- светлая тема, клавиатурный focus, ARIA, touch targets и reduced motion;
- Swagger по адресу `/api/docs`.

## Архитектура

```text
apps/web        React 19 + Vite + Router + Query + 2ГИС MapGL JS API
    │ REST / Socket.IO
apps/server     NestJS + JWT + Prisma + PostgreSQL
    │
PostgreSQL      доменные данные и аудит
uploads/        локальный FileStorageProvider для development

packages/shared    общие enum, типы и Zod
packages/platform  MiniAppPlatform и адаптеры
packages/ui        базовые доступные компоненты
```

Сервер является единственным источником прав, автора и статуса. `ProblemStateMachineService` проверяет каждый переход. После отчёта исполнитель переводит задачу только на проверку оператора. Для обычной проблемы нужно два независимых подтверждения и два независимых положительных голоса результата. Опасные категории сразу получают `CRITICAL` и `OPERATOR_REVIEW`.

## Требования

- Node.js 22+;
- pnpm 10+ (версия зафиксирована в `packageManager`);
- PostgreSQL 16+ или Docker Desktop;
- ключ 2ГИС MapGL JS API для клиентской карты;
- серверный ключ Геокодера 2ГИС для поиска и обратного геокодирования.

## Установка и запуск через pnpm

```bash
pnpm install
copy .env.example .env
docker compose up -d postgres
pnpm db:generate
pnpm db:migrate
pnpm db:seed
pnpm dev
```

На macOS/Linux используйте `cp .env.example .env`. Клиент: `http://localhost:5173`, API: `http://localhost:3000/api`, Swagger: `http://localhost:3000/api/docs`.

Для быстрого прототипирования без файла миграции допустимо `pnpm db:push`, затем `pnpm db:seed`.

### Проверка на телефоне в одной сети

Запустите `pnpm dev` и откройте на телефоне `http://<IPv4 компьютера>:5173` (адрес можно посмотреть командой `ipconfig`). Компьютер и телефон должны быть подключены к одному роутеру. Терминал с приложением и Docker Desktop должны оставаться запущенными.

В `.env` используйте `VITE_API_URL="/api"` и `VITE_SOCKET_URL=""`. Vite передаёт API-запросы, изображения и Socket.IO на локальный сервер через один порт 5173. После изменения `.env` перезапустите `pnpm dev`.

Если брандмауэр Windows блокирует соединение, выполните из папки проекта в PowerShell **от имени администратора**:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\allow-lan-windows.ps1
```

Правило разрешает порт 5173 только для локальной подсети и частного сетевого профиля. Геолокация браузера на телефоне может требовать HTTPS; адрес и точку на карте можно выбрать вручную.

## Запуск через Docker Compose

```bash
docker compose up --build
```

После старта сайт доступен на `http://localhost:4173`. Compose ждёт healthcheck PostgreSQL, применяет Prisma schema, заполняет seed и запускает API. Загруженные изображения и данные PostgreSQL находятся в именованных volumes.

PostgreSQL опубликован на `localhost:55432`, чтобы не конфликтовать с локальной установкой на стандартном порту. На Windows с Docker Desktop/Buildx 0.32 и кириллицей в пути рабочей папки используйте `pnpm docker:up:windows`: команда собирает тот же Compose из одноразового ASCII-контекста и удаляет его после старта. Это обход ограничения gRPC-метаданных Buildx; исходники и volumes не копируются обратно и не теряются.

## Переменные окружения

Скопируйте `.env.example` в `.env`. Важные ключи:

- `DATABASE_URL` — PostgreSQL connection string;
- `JWT_SECRET` — минимум 32 случайных символа вне development;
- `WEB_ORIGIN` — разрешённые origins через запятую;
- `VITE_API_URL`, `VITE_SOCKET_URL` — публичные адреса клиента;
- `VITE_DGIS_MAPS_API_KEY` — браузерный ключ 2ГИС MapGL JS API; ограничьте его доменами приложения;
- `DGIS_API_KEY` — серверный ключ Геокодера 2ГИС; он не передаётся в клиентскую сборку;
- `UPLOAD_DIR`, `MAX_UPLOAD_MB` — локальное хранилище;
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` — опциональный Telegram-транспорт.

Реальные секреты не должны попадать в Git. Серверные ключи нельзя помещать в `VITE_*`: такие значения доступны браузеру. Если ключ карты не задан, интерфейс показывает понятное состояние настройки без скрытого возврата к другому картографическому сервису; если не задан ключ геокодера, адрес остаётся доступен для ручного ввода.

## Демонстрация полного сценария

1. Войти Анной и создать обращение категории «Освещение» с точкой и фото.

4. Переключиться на оператора, открыть очередь, назначить «Горсвет Новосибирска» и срок.
5. Переключиться на исполнителя, принять задачу, добавить фото после ремонта и отчёт.

7. Михаил и Елена голосуют «Устранено полностью».

## Telegram Mini App

Официальный SDK подключён в `apps/web/index.html`. Если `window.Telegram.WebApp` отсутствует, приложение безопасно использует `BrowserPlatformAdapter`.

В Telegram адаптер вызывает `ready()` и `expand()`, учитывает тему, safe area, BackButton, haptics, start parameter и share. Для отображения можно читать `initDataUnsafe`, но авторизация всегда отправляет исходный `initData` на `/api/auth/telegram`. Сервер проверяет HMAC, `auth_date` и только затем создаёт JWT.

### BotFather и HTTPS

1. Создайте бота через `/newbot` в BotFather.
2. Разместите приложение на HTTPS-домене с действующим сертификатом.
3. В BotFather выполните `/newapp`, выберите бота и укажите HTTPS URL.
4. Добавьте домен через `/setdomain`, если этот пункт требуется текущим интерфейсом BotFather.
5. Задайте `TELEGRAM_BOT_TOKEN` только в окружении API и добавьте тот же публичный origin в `WEB_ORIGIN`.

Telegram требует HTTPS. Для локальной проверки используйте безопасный HTTPS tunnel и не публикуйте токен в URL/репозитории. Если токен пуст, вход по браузерному JWT и внутренние уведомления продолжают работать; бот-сообщения просто не отправляются.

## Платформенный слой и MAX

`MiniAppPlatform` определяет пользователя, тему, BackButton, haptics, внешние ссылки, start parameter, события, sharing и ready. Реализованы `BrowserPlatformAdapter` и `TelegramPlatformAdapter`. `MaxPlatformAdapter` намеренно не вызывает выдуманные API: в нём оставлены безопасные no-op точки, куда после публикации официального MAX Bridge добавятся получение подписанного payload, theme, back, haptic, link и share.

## Проверки

### Личный кабинет

Маршрут `/profile` доступен каждой роли через меню и аватар в шапке:

- житель: собственные обращения и подписки, вклад в район, достижения и история репутации;
- оператор: показатели городской очереди, просроченные и спорные обращения, исполнители и личная история действий;
- исполнитель: текущие задачи своей организации, проверка отчётов, сведения об организации и личная история действий;
- администратор: показатели аккаунтов, организаций и миссий, переходы к управлению и личная история действий.

Во вкладке «Личные данные» можно изменить отображаемое имя. Электронная почта, роль, район и организация доступны для просмотра. `PATCH /api/profile` принимает только имя по общей Zod-схеме, изменяет текущего пользователя из проверенной сессии и записывает действие в аудит. `GET /api/profile/overview` формирует показатели по серверной роли; переназначенные задачи исключаются из кабинета прежней организации. Данные обращений обновляются через Socket.IO, показатели дополнительно обновляются каждые 30 секунд.

Проверка кабинетов: `pnpm test:e2e account.spec.ts`. Сценарии охватывают Chrome на компьютере, мобильный Chrome и Safari, ширину 360 px, переходы по роли, валидацию, сохранение имени, защиту доступа, ошибки и пустые состояния.

## Ограничения MVP

- координаты хранятся как `latitude/longitude`; для production-поиска и полигонов районов нужен PostGIS;
- похожесть основана на категории, активном статусе и Haversine-расстоянии, без семантической модели;
- файлы хранятся локально; интерфейс следует заменить реализацией S3/MinIO для нескольких API-инстансов;
- Telegram bot delivery оставлен за очередью/transport-адаптером; без токена работают только внутренние уведомления;
- MAX Bridge не подключён до появления официального контракта;
- расширенная аналитика демонстрационная, без BI-экспорта и исторических срезов;
- rate limit хранится в памяти одного API-процесса; для production нужен Redis-backed storage;
- геокодер вызывается через API приложения; для большого production-трафика нужен кэш и контроль квот 2ГИС.


### Надёжный локальный запуск

На Windows откройте `start-pulse.cmd` в корне проекта или выполните `pnpm dev`.
Команда сама запускает Docker Desktop при необходимости, поднимает существующую базу PostgreSQL и ждёт её готовности, затем запускает API и дожидается успешной проверки API с базой перед запуском сайта. Данные не сбрасываются, seed автоматически не выполняется.

Оставляйте терминал и Docker Desktop открытыми. После перезагрузки компьютера запускайте приложение заново этой же командой. Не запускайте один `apps/web`: без API вход не работает. Если одна из двух служб завершится, общий процесс остановит вторую — ошибка останется в терминале.

Проверка готовности: `http://localhost:5173/api/health` должна вернуть `status: ok` и `database: ok`. Если сайт открыт, но этот адрес возвращает ошибку, проблема в API или базе, а не в пароле. Ошибки запуска Docker нужно устранять по сообщению Docker Desktop; запуск приложения останавливается с объяснением, не удаляя базу.

Повторный `pnpm dev` проверяет уже работающий API и сайт: если оба исправны, сообщает, что приложение запущено, без второго экземпляра. При частично занятых портах предлагает закрыть старый запуск через Ctrl+C, вместо повторной компиляции и ошибки EADDRINUSE.
